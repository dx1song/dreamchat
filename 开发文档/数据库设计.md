# 星梦智能助手 数据库设计文档

## 一、概述

| 项目 | 说明 |
|------|------|
| 数据库 | SQLite |
| 字符编码 | UTF-8 |
| 表数量 | 3 张 |
| ORM | SQLAlchemy 2.0（Python 侧） |
| 外键 | 需开启 `PRAGMA foreign_keys = ON` |

三张表及关系：

- `users`（用户表）—— 1 对多 `constellation_records`
- `users`（用户表）—— 1 对多 `dream_records`

```
users 1 ──── N constellation_records
users 1 ──── N dream_records
```

## 二、通用约定

1. 所有表均含自增主键 `id`，类型 `INTEGER PRIMARY KEY AUTOINCREMENT`。
2. 时间字段 `created_at` 统一 `DATETIME`，默认 `CURRENT_TIMESTAMP`（UTC），展示时由前端转本地。
3. 多选字段（`focuses`）用 `TEXT` 存 JSON 数组字符串，如 `["性格","事业"]`。
4. 枚举字段用 `TEXT` 存中文值，取值范围由应用层（Pydantic）校验，并在数据库层用 `CHECK` 兜底。
5. 完整报告用 `TEXT` 存 JSON 字符串（结构见各表说明），历史详情页直接解析展示。
6. 密码只存 bcrypt 哈希，不存明文。

## 三、表结构设计

### 3.1 users（用户表）

| 字段 | 类型 | 约束 | 描述 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 用户主键 |
| username | TEXT | NOT NULL, UNIQUE | 用户名，3-20 位字母/数字/下划线，存小写（不区分大小写） |
| email | TEXT | NOT NULL, UNIQUE | 邮箱，标准格式，唯一 |
| password_hash | TEXT | NOT NULL | 密码哈希（bcrypt） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 注册时间 |

### 3.2 constellation_records（星座分析记录表）

| 字段 | 类型 | 约束 | 描述 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 记录主键 |
| user_id | INTEGER | NOT NULL, FK → users.id | 所属用户 |
| birth_date | TEXT | NOT NULL | 出生日期，格式 `YYYY-MM-DD`，年份 1970-2008 |
| gender | TEXT | NOT NULL | 性别：男 / 女 |
| relationship | TEXT | NOT NULL | 情感状态：单身 / 恋爱 / 已婚 / 离异 / 丧偶 / 其他 |
| job | TEXT | NOT NULL | 职业身份，≤50 字 |
| focuses | TEXT | NOT NULL | 测算关注点，JSON 数组，如 `["性格","事业"]`，至少 1 项 |
| zodiac | TEXT | NOT NULL | 推算出的星座类型，如「白羊座」（用于列表展示） |
| report_content | TEXT | NOT NULL | 完整报告 JSON（结构见下） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 生成时间 |

**report_content JSON 结构示例：**

```json
{
  "zodiac": "白羊座",
  "personality": "你是典型的白羊座——热情、直率、行动力强……",
  "fortune": {
    "career": { "level": "★★★★☆", "desc": "上升期，主动争取会有意外收获" },
    "love":   { "level": "★★★☆☆", "desc": "多一些耐心倾听，关系会更融洽" },
    "health": { "level": "★★★★☆", "desc": "精力充沛，注意规律作息" },
    "wealth": { "level": "★★★☆☆", "desc": "平稳为主，避免冲动消费" }
  },
  "lucky_color": "珊瑚红",
  "lucky_number": "7",
  "advice": ["本周适合推进搁置已久的计划", "做决定前不妨多等一天"]
}
```

> `zodiac` 列与 JSON 内 `zodiac` 字段冗余，独立列用于历史列表快速查询，JSON 用于详情完整回放。

### 3.3 dream_records（解梦记录表）

| 字段 | 类型 | 约束 | 描述 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 记录主键 |
| user_id | INTEGER | NOT NULL, FK → users.id | 所属用户 |
| dream_content | TEXT | NOT NULL | 梦境内容，10-500 字 |
| dream_time | TEXT | NOT NULL | 做梦时间：今晚 / 昨晚 / 近三天内 / 近一周内 / 更早 |
| gender | TEXT | NOT NULL | 性别：男 / 女 |
| age | TEXT | NOT NULL | 年龄档：18-25 / 26-35 / 36-45 / 46-55 / 55+ |
| job | TEXT | NOT NULL | 职业，≤50 字 |
| mood | TEXT | NULL | 近期状态，≤50 字，**选填** |
| focuses | TEXT | NOT NULL | 解梦关注点，JSON 数组，如 `["事业","感情"]`，至少 1 项 |
| dream_keyword | TEXT | NOT NULL | 梦境关键词（列表展示用），如「梦见蛇」 |
| report_content | TEXT | NOT NULL | 完整报告 JSON（结构见下） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 生成时间 |

**report_content JSON 结构示例：**

```json
{
  "core_meaning": "梦中的蛇往往象征着潜意识中的能量与转变……",
  "interpretations": [
    { "focus": "事业", "content": "从事业角度看，蛇的出现常被视为智慧与机遇的信号……" }
  ],
  "advice": ["面对新变化时，先观察再行动", "留意身边主动靠近的机会", "把反复思考的事情写下来"],
  "verdict": "好梦"
}
```

> `dream_keyword` 由后端在调用 AI 时一并提取（或从内容生成），独立列用于列表展示「梦境关键词 + 日期」。

## 四、索引设计

| 表 | 索引名 | 字段 | 用途 |
|----|--------|------|------|
| users | 唯一约束 | username | 登录/注册查重 |
| users | 唯一约束 | email | 注册查重 |
| constellation_records | idx_constellation_user_time | (user_id, created_at DESC) | 按用户查历史，倒序分页 |
| dream_records | idx_dream_user_time | (user_id, created_at DESC) | 按用户查历史，倒序分页 |

## 五、约束与规范

1. **数据隔离（硬性）**：查询/更新/删除记录时，必须同时携带 `user_id` 条件，禁止仅凭记录 `id` 操作。
2. **枚举校验**：`gender`、`relationship`、`dream_time`、`age` 等在应用层用 Pydantic 枚举校验，数据库层用 `CHECK` 兜底。
3. **用户名字符集**：应用层统一 `lower()` 后入库，保证「Alice」与「alice」视为同一用户。
4. **报告完整性**：`report_content` 只在 AI 调用成功时写入；失败/超时不落库。
5. **删除策略**：用户表删除时级联删除其记录（`ON DELETE CASCADE`，为未来「注销账号」预留）。

## 六、建表 SQL

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE users (
    id            INTEGER  PRIMARY KEY AUTOINCREMENT,
    username      TEXT     NOT NULL UNIQUE,
    email         TEXT     NOT NULL UNIQUE,
    password_hash TEXT     NOT NULL,
    created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE constellation_records (
    id             INTEGER  PRIMARY KEY AUTOINCREMENT,
    user_id        INTEGER  NOT NULL,
    birth_date     TEXT     NOT NULL,
    gender         TEXT     NOT NULL CHECK (gender IN ('男','女')),
    relationship   TEXT     NOT NULL CHECK (relationship IN ('单身','恋爱','已婚','离异','丧偶','其他')),
    job            TEXT     NOT NULL,
    focuses        TEXT     NOT NULL,
    zodiac         TEXT     NOT NULL,
    report_content TEXT     NOT NULL,
    created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
CREATE INDEX idx_constellation_user_time ON constellation_records(user_id, created_at DESC);

CREATE TABLE dream_records (
    id             INTEGER  PRIMARY KEY AUTOINCREMENT,
    user_id        INTEGER  NOT NULL,
    dream_content  TEXT     NOT NULL,
    dream_time     TEXT     NOT NULL CHECK (dream_time IN ('今晚','昨晚','近三天内','近一周内','更早')),
    gender         TEXT     NOT NULL CHECK (gender IN ('男','女')),
    age            TEXT     NOT NULL CHECK (age IN ('18-25','26-35','36-45','46-55','55+')),
    job            TEXT     NOT NULL,
    mood           TEXT,
    focuses        TEXT     NOT NULL,
    dream_keyword  TEXT     NOT NULL,
    report_content TEXT     NOT NULL,
    created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
CREATE INDEX idx_dream_user_time ON dream_records(user_id, created_at DESC);
```

## 七、是否需要其他表

**本期不需要额外表**，理由：

1. 认证采用 **JWT 无状态**，不需要 session/token 表。
2. 关注点、年龄档、情感状态等均为**固定枚举**，无需字典表。
3. 星座日期对照表**硬编码**在代码中，无需表。
4. 「记住我」由 token 有效期体现，无需单独字段或表。

**未来可选扩展（本期不做）**：

| 表 | 场景 |
|----|------|
| password_reset_codes | 若后续做「忘记密码/邮箱验证」 |
| login_logs | 若需要登录日志/审计 |
| report_feedback | 若需要报告点赞/反馈 |
